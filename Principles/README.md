# Design Principles

Design principles are the foundation for writing maintainable object-oriented code. Learn these before design patterns.

## Recommended Order

1. [KISS](KISS/README.md)
2. [DRY](DRY/README.md)
3. [YAGNI](YAGNI/README.md)
4. [SOLID](Solid/README.md)

## Principles In This Folder

| Principle | Meaning | Folder |
|---|---|---|
| KISS | Keep It Simple | [KISS](KISS/README.md) |
| DRY | Do not repeat yourself | [DRY](DRY/README.md) |
| YAGNI | Do not build what is not needed yet | [YAGNI](YAGNI/README.md) |

## Why Study These First?

Design patterns make more sense after you understand principles. For example:

- Strategy helps with Open/Closed Principle.
- Observer helps reduce direct coupling.
- Factory patterns hide object creation.
- Builder avoids large confusing constructors.

Patterns are practical applications of principles.
